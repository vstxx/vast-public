# Translator for Vast

Branch `feat/translator-for-vast` (from `feat/native-extensions-runtime` 381cb99). Electron 45.0.0-vast-r1 (Chromium 156) with the patched ECE compatibility runtime, Windows 11, i7-14650HX. Source: `resources/first-party-extensions/translator-for-vast/`. Package: `artifacts/Translator-for-Vast-1.0.0.vext`.

## 1. Architecture

```
toolbar (vast.contributes, action "popup")   page menu (chrome.contextMenus via ECE)
          │                                              │
          ▼                                              ▼
   Chrome action popup ──────► MV3 service worker ◄──── content script (injected on demand)
                                 │  validates every message, routes, injects, owns menus
                                 ▼
                     offscreen document (created on demand, closes itself when idle)
                                 │  engine host: priority queue, cancellation, idle release
                                 ▼
                       dedicated Worker: Bergamot WASM (SIMD), up to 2 models
                                 │
                     CacheStorage (verified model bytes, per workspace session)
                                 ▲
         storage.googleapis.com/moz-fx-translations-data--303e-prod-translations-data/ (only network origin)
```

| Layer | Implementation | Idle cost |
| --- | --- | --- |
| Vast integration | `vast.contributes.toolbar` (verified SVG icon, `popup` action), Chrome action popup and options page, `chrome.contextMenus` (selection, page, show original) | No Native host (state `idle`), no tab-event demand |
| Controller | MV3 service worker; no state of its own, safe to stop at any time | Chromium suspends it after inactivity |
| Content | `content.js` injected into the top frame only after a user action or an automatic-translation rule; `content.css` via `insertCSS` | None on pages that were not translated |
| Engine | Offscreen document + dedicated Worker, created on the first request, released after `idleSeconds` (default 30 s) | None: the document and worker do not exist while idle |
| Models | Packaged catalog, streamed gzip download, SHA-256 before storage, CacheStorage | Disk only |

Decisions and deviations from the brief:

- **Toolbar through `vast.contributes`, menus through `chrome.contextMenus`.** The Native toolbar action gives the extension its own icon next to the address bar without a background host; the Chrome action popup is the single popup implementation. Selection and page menus use ECE's `chrome.contextMenus`, which delivers `selectionText` to the worker in the right session. Nothing is duplicated across the two layers.
- **Host access is declared (`http://*/*`, `https://*/*`) instead of relying on `activeTab`.** Measured on the running binary: neither a context-menu click nor opening the popup grants `activeTab` in Electron/ECE; `scripting.executeScript` fails without host permission. No content script is declared; the extension injects only after a user action. The install preview discloses the host access.
- **Model catalog is packaged, not fetched.** Hashes, sizes and paths come from `catalog/models.json` (generated by `tools/refresh-catalog.mjs`, which joins Mozilla Remote Settings with Mozilla's model registry and refuses mismatches). The extension never downloads metadata; the only runtime network requests are model files. New models arrive with extension updates.
- **One model source.** The Remote Settings CDN answers HTTP 406 to Chromium user agents (verified with curl); Mozilla's model bucket on Google Cloud Storage serves the same files gzip-compressed. The manifest `connect-src` allows only that bucket path, so even a bug cannot reach another host from extension pages (verified: `fetch('https://example.com')` from the worker fails).
- **No translator-specific code in Vast Core.** Browser-side changes are generic: the Hub's WebAssembly policy, and the compatibility matrix now reports packaged WebAssembly as supported on the patched runtime (measured).
- **Models are per workspace.** Each persistent workspace is a separate extension session with its own CacheStorage. There is no trusted generic mechanism for sharing extension storage across sessions, so none was added; a second workspace downloads a model again. Private and ephemeral workspaces do not load extensions.

### Engine lifecycle

`uninitialized → loading → ready ⇄ translating → idle → released`, `error` from any state. Requests, queued jobs and downloads keep the engine alive; the idle countdown starts when all are finished. Release terminates the worker (the only way to return a WebAssembly heap) and closes the offscreen document; the next request recreates both. Selection requests jump ahead of queued page batches. Jobs carry a tag per tab/frame/document; leaving or restoring a page cancels its queued batches. A worker crash rejects pending calls and is retried once; a route evicted between load and use is reloaded once.

### Page translation

Segmentation, scheduling and restore bookkeeping are adapted from Glossa: block-level units with inline tags carried through Bergamot's HTML mode, page elements numbered (`data-tfv-id`) so the translation reuses them, placeholders for `translate="no"`, `.notranslate`, URLs, e-mail addresses and long numbers, `IntersectionObserver` for visible-first batching (24 units / 6000 characters), a MutationObserver only while a page is translated, debounced and limited to the changed subtrees, and a record of written output so the page's own re-renders are never sent back as source text. Observer work is limited to 8 passes per 5 seconds with a timed backoff; queued changes are processed afterward. Redundant changed roots are removed by walking ancestors, in linear rather than quadratic work for a large insertion.

Changed for Vast:
- **Renderer rewritten as an allowlist** (see Security).
- **Serialisation per batch.** Numbering and serialising every unit up front was one long task on large pages; units are now prepared when their batch is sent.
- Background tabs wait until visible; batches yield to the event loop.
- Form values, password fields, hidden inputs, textareas, selects and `contenteditable` regions are never sent or changed.

### Selection and single words

The page menu shows `Translate "<selection>"` for any selection, including a double-clicked word. The panel lives in a closed shadow root on its own host element, styled with a constructed stylesheet (not subject to the page's `style-src`), anchored below or above the selection, clamped to the viewport, repositioned on scroll, with Escape, outside click, focus return, copy, and a target-language picker. It shows a download offer with size when the model is missing. The optional selection button (off by default) is a separate 3 KB registered script. No dictionary data is shown: Bergamot provides translations only.

### Automatic translation

Opt-in. While "always translate" lists a language, a 0.8 KB script is registered for websites (minus "never translate" sites). It runs once per document, sends the declared language and a short sample to the worker, and the page is translated only when detection matches and the model is already downloaded. It never downloads, never observes the DOM, and is unregistered when the list is empty.

Audit notes:
- Glossa's checked-out glue differs from its own lock because of line-ending conversion; the glue here is taken from the Firefox tree and verified against the lock (`.gitattributes` keeps vendor files byte-exact).
- The glue contains no `eval` or `new Function` (Mozilla patched the Emscripten invokers); its only dynamic-code surface is WebAssembly compilation of the packaged binary.
- Engine major 4 reads model major 3 (`MODEL_MAJOR`/`ENGINE_RELEASE` in `src/shared/catalog.ts`; installed models are stamped with both).
- Glossa downloads gzip files from the bucket with no size limit and decompresses without an output cap; here every response is limited to the catalog's gzip size and the decompressed stream to the exact file size.
- Glossa's renderer imports model-generated elements and strips a blocklist (`script`, `on*`, `javascript:`); here generated elements are never inserted.
- Firefox-only parts (background page engine, `openOrClosedShadowRoot`, mirror permissions) and Chrome's built-in Translator API path were not ported. Closed shadow roots are skipped in Vast.
- 8 catalog directions are not offered: `az-en`, `bs-en`, `hr-en`, `sr-en`, `en-zh-Hans`, `en-zh-Hant`, `zh-Hans-en`, `zh-Hant-en`. Their Remote Settings models have no matching file in the bucket, and the CDN refuses Chromium.
- Glossa ships unit tests (happy-dom) and Playwright smokes; they were read, not run, since the code paths here differ.

## 3. Features

Working, verified in the Vast runtime (section 7): page translation with restore, selection and single-word translation from the page menu, the toolbar popup, settings with model manager, on-demand verified model downloads, offline use, automatic translation rules, never-translate sites/languages, replace and side-by-side display, EN↔PL plus pivot routes through English, English and Polish interface.

Not provided: keyboard shortcut (Chrome commands are not dispatched by the runtime), dictionary data, translation inside closed shadow roots or cross-origin frames (top frame only), sharing models between workspaces, automatic re-translation after SPA route changes that replace the whole document body without mutations visible to the observer.

## 4. Vast integration

Uses only existing generic surfaces: `vast.contributes.toolbar` (from the Native runtime work), ECE `chrome.action` popup, options page, `chrome.contextMenus`, `chrome.scripting`, `chrome.offscreen`, `chrome.storage`, `chrome.i18n.detectLanguage`.

Browser and Hub changes (generic, translator-agnostic):

| File | Change |
| --- | --- |
| `extensions-hub/src/validation.ts` | WebAssembly policy for non-curated packages: `.wasm` files must be declared in `vast_wasm.modules`, start with the WebAssembly header, and live in a Manifest V3 package whose extension-page policy is `'self'` plus `'wasm-unsafe-eval'` only (no `'unsafe-eval'`, remote or relaxed `worker-src`/`script-src-elem`/`default-src`, object sources limited to `'self'`/`'none'`). `WebAssembly` stays prohibited in content scripts, in packages without declared modules and in every package without `vast_wasm`. `'wasm-unsafe-eval'` without declared modules is rejected. Module provenance is the Hub's own record of reviewed SHA-256 values (currently Bergamot 0.6.0); an unrecorded module and a package without a `connect-src` restriction go to manual review. | `scripts/run-isolated-electron-e2e.cjs`, `package.json` | translator targets and scripts |

Existing published artifacts (Adblocker 1.0.0/1.1.0, IDU+ 0.3.8, Bitwarden, Proton Pass) produce identical Hub validation results before and after the change.

## 5. Security

- **Execution:** only packaged code. The engine binary is pinned by hash in the build and recorded by the Hub. Model downloads are data passed to Bergamot; they are never compiled or executed. Extension pages run under `script-src 'self' 'wasm-unsafe-eval'; object-src 'none'; base-uri 'none'; connect-src 'self' <model bucket>`.
- **Model integrity:** packaged catalog (hash authority signed with the package), one HTTPS bucket prefix, `redirect: 'error'`, no credentials or referrer, exact gzip size cap while streaming, decompression into a buffer of exactly the published size (overflow aborts), SHA-256 before storage. Installed only after every file is stored; re-verified (size and SHA-256) before every load, and a damaged file is deleted and reported. One download per pair at a time, cancellable, at most 3 attempts. Storage headroom is checked before a download.
- **Messaging:** the engine accepts requests only from this extension's service worker (`sender.url`, no tab); content scripts reach every extension page with `runtime.sendMessage`, so this check matters. The worker treats content-script messages as untrusted: types, language codes and sizes are validated (64 fragments, 12 000 characters each, 48 000 per request; 5 000-character selections; 4 000-character samples). Pages accept commands only from the worker. Engine jobs are tagged per tab, frame and document.
- **DOM:** model output is parsed in an inert document and rebuilt as text nodes plus the unit's own page elements (moved in replace mode, shallow-copied without ids and inline handlers otherwise). Elements and attributes that the unit did not have are dropped, including scripts, images, frames, forms, SVG, styles, `javascript:` URLs and handlers (DOM test with hostile output). Attributes and labels are written as text. Panels use closed shadow roots and react only to trusted events.
- **Privacy:** no telemetry, analytics, account, remote configuration or cloud fallback. Requests contain only the model file path. Detection uses the browser's local CLD3. Private and ephemeral workspaces keep Vast's existing policy (no extension sessions).

## 9. Limitations

- **The reported `lzt.market` crash remains unattributed.** On a fresh profile and on a separate copy of `C:\Users\jnowa\VastTestSession\profile`, the live `ru-RU` homepage performed RU→EN→PL translation, a selection translation at the engine boundary, and a minute of scrolling/dynamic updates without a spontaneous process exit, a `render-process-gone`/`child-process-gone` event or a crash dump. The earlier site state ended at 114/114 units; a later, larger live state ended at 249/254 (five results were not applied, with no reported error). The copied-profile run reached a 417 MB WASM heap and about 544 MB extension-process private memory during translation; the final run's extension process stayed near 503 MB. The only recorded exit code 1 was caused deliberately by `taskkill` in the harness. Windows recorded an `electron.exe` `AppHangTransient` earlier on 28 October, but it has no page/process evidence tying it to this report. Therefore no specific main, guest, extension or GPU process can honestly be named as the crashed one. The reproducible quadratic SPA-root walk (359,400 ancestor checks for 600 siblings), mutation-loss race, and three-model retention were fixed or bounded; these are confirmed hazards, not a proven historical crash cause. The worker now holds at most two models and refuses a load whose projected WASM heap exceeds 640 MiB with an error surfaced by the UI. No extension can guarantee that Chromium itself never crashes.
- **Host access:** `activeTab` is not granted by popup or context-menu actions in Electron/ECE, so `http://*/*` and `https://*/*` host access is declared and disclosed at installation. Scripts are still injected only on demand or by the opt-in automatic rule.
- **Catalog availability:** 8 Remote Settings directions are unavailable because the GCS bucket has no matching model: `az-en`, `bs-en`, `hr-en`, `sr-en`, `en-zh-Hans`, `en-zh-Hant`, `zh-Hans-en`, `zh-Hant-en`.
- **Workspaces:** models are downloaded and stored separately in each persistent workspace. Private and ephemeral workspaces do not load extensions. Two simultaneous ready workspaces consume two engine heaps.
- **Page coverage:** only the top frame and open shadow roots are translated. Closed shadow roots and iframes are not translated. A wholesale SPA body replacement without an observed mutation can require another user action.
- **Controls and quality:** no keyboard shortcut, because this ECE runtime does not dispatch Chrome commands; no dictionary data; the documented model errors in the quality set remain. Sustained SPA changes can be delayed by the observer backoff.
