# Vast 2 Chromium migration progress

Last updated: 2026-07-16

## Current milestone

Phase 0 and Phase 1 are complete. The real upstream `//chrome:chrome` Windows x64 build succeeds at the exact pinned Chromium commit, and its staged `Vast.exe` passes the automated Phase 2 acceptance runner. The verified native runtime opens `accounts.google.com` as an ordinary top-level tab, supports multiple tabs, persistent cookies after restart, service workers, downloads, popups, the Permissions API, and DevTools, and contains no Electron-named runtime or security-bypass GN flags. Patch `0018` establishes the Vast Shell alpha: regular-profile `chrome://newtab` resolves to the profile-scoped dashboard, native frame/tab/toolbar/omnibox roles use the tested Vast palette, and the workspace rail renders the safe keyed-service projection after restart. Patches `0019`–`0022` move Vast ownership beyond page content with a persistent native Chromium Views workspace control, selection from both its checked menu and the WebUI rail, and a browser-window adapter that maps validated workspaces to real native tab groups. Selection is an atomically written, migration-journal-scoped profile overlay; it survives restart without editing imported `vast-data.json`. A bounded profile-local registry now retains exact Chromium group tokens across forced process restart without storing URLs, tab contents, or history. Switching expands Beta, collapses other Vast groups, assigns existing and newly opened unpinned/ungrouped tabs, and never claims unrelated user groups. The 33-test native suite, synthetic fixture, supplied real backup, Windows UI Automation, complete 22-patch composition check, and full staged acceptance verify this path. Post-`0022` acceptance passes in `chromium-port/.reports/phase2-acceptance-20260716-185834.json`; only the human clean-profile credential sign-in remains as the Phase 2 gate. No installed Vast binaries or active user profile have been modified. Electron 1.0.11 remains the production baseline.

## Active risks and blockers

1. Chromium rebuilds remain large even though narrow resource changes are fast incrementally. The checkout stays outside the Vast repository and uses the pinned commit.
2. Workspace selection and exact native group identity survive restart, but per-workspace last-active-tab identity remains process-local. Safe stale-token compaction, create/rename/delete, editable settings, side panels, and most product services are not yet connected to Chromium. The adapter must continue to avoid inferring ownership from unnamed or unrelated user groups.
3. An open Chromium distribution cannot bundle Chrome Sync, Google Chrome branding/private API credentials, Widevine without licensing, or every proprietary codec.

## Next executable actions

1. Persist a URL-free per-workspace last-active-tab reference through Chromium's native session model and add conservative stale group-token compaction without claiming user groups.
2. Map legacy Electron workspace membership into native tabs through an explicit, rollback-safe migration rather than storing browsing state in the WebUI registry.
3. Extend the profile-scoped workspace command service with safe create/rename/archive operations and explicit product-data ownership rules.
4. Begin the editable settings/Prefs adapter and feed approved theme changes into the shell color provider.
5. Design the production browser-process file-picker/root-selection authority; do not reuse development command-line switches as the shipping UI.
6. Run the manual clean-profile Google website credential sign-in checklist without automating credentials.
